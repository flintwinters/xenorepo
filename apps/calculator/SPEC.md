# Calculator — Product Specification

## User problem and product intent

A person needs a small, dependable calculator for ordinary arithmetic without carrying state
between visits. The product succeeds when a complete calculation can be submitted through a plain
form, the authoritative server returns an explicit result, and exceptional arithmetic produces a
useful field error. Calculator is deliberately stateless: it stores no calculations, preferences,
or history.

## Feature inventory

- MonoForm number fields for left and right operands and an operator selection.
- Server-side addition, subtraction, multiplication, and division.
- A visible response containing the normalized expression and numeric result.
- Explicit field-level division-by-zero errors and finite-number enforcement.
- A generated responsive page with no calculator-owned frontend code.

## Walking skeleton

The first shippable slice presents the `calculate` action generated by MonoForm from FastAPI's
OpenAPI schema. A user enters two finite decimal operands, selects `add`, `subtract`, `multiply`, or
`divide`, and submits the form. `POST /api/calculate` performs the operation and returns the
normalized expression and result. Division by zero is rejected against the right-operand field.

The app declares a native `monoform` artifact and has no app-authored TypeScript or CSS. The form
holds only an unsubmitted draft; every result is computed by FastAPI and disappears on reload. The
endpoint enforces same-origin browser mutations and stores nothing.

## Real-world pilot and acceptance

Use the running app to total two prices, subtract a discount, multiply a quantity, divide a total,
and provoke division by zero. Confirm every successful response agrees with an independent
calculation, the invalid divisor is marked, a reload clears the visible outcome, and the complete
generated form remains usable on wide and narrow screens.

Automated acceptance covers all four server operations, decimal and negative operands,
division-by-zero validation, same-origin enforcement, repeated stateless requests, OpenAPI-derived
MonoForm generation, self-contained FastAPI delivery, and deterministic wide/narrow visual checks.

## Deferred scope

Calculation history, memory registers, persistence, chained expressions, percent and sign buttons,
scientific functions, parentheses, arbitrary precision, localization, and currency conversion are
intentionally deferred. Calculator arithmetic remains app-owned server policy; only its generic form
rendering belongs to Monotools.
